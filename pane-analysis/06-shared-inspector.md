# Shared inspector behavior and action placement

## Scope

Read with the workflow reports and [validation](07-validation.md). This chapter compares the common pane mechanics, not resource-specific content or native operating-system behavior. Iceon retains Astryx and its Rust-owned engine by design; it should not reproduce Freelens CSS, Electron or raw-object boundaries merely for screenshot similarity.

Source roots: Iceon `src/...`, `src-tauri/...`, `tests/...`; Freelens `packages/...`. Revisions are pinned in the [index](README.md).

## Shared content that remains incomplete

1. **Metadata:** Iceon renders Name/Namespace/Created/UID/resourceVersion and selected columns, then flat sections (`ResourceInspector.tsx:227-243`). Freelens's shared metadata additionally renders labels, annotations, finalizers, Deleted, owners and managed-field expanders, with UID/version/selfLink hidden by default (`packages/core/src/renderer/components/kube-object-meta/kube-object-meta.tsx:63,99-160`). Screenshot-visible Labels are not the same data as spec Selector. Implement bounded reviewed metadata, not arbitrary object JSON.
2. **Conditions:** generic Iceon facts include type/status/reason/transition, not condition messages/heartbeat or equivalent tooltips. Node additionally has badge data, creating duplicate condition presentation. Source-only field coverage is not proof of readable large-collection behavior.
3. **Related collections:** current DTO is one `item`, allowlisted scalar `related` links, flat `sections`, not child-resource tables (`details.rs:34-44`). New child sections need identity, independent reads, bounded pagination, loading/empty/denied/error/stale/partial states and cancellation. Faking them with count strings is not parity.
4. **Object Events:** generic inspector has no associated-event collection. The separate Event pane and Event -> involved-object link do not implement the reverse parent -> events workflow. Preserve UID filtering and explicit text bounds; Node source has an upstream name/UID heuristic that must not be copied blindly.
5. **Metrics:** table/current utilization data exists but no time-ranged Node/workload detail charts. The screenshot's unavailable state does not justify adding a nonfunctional period selector.

## Action classification and implementation order

- **Inspection/local UI:** open/close, resize, expand, Show/Hide managed fields, resource links, sort/filter, current read refresh. Most must remain possible when write rights are denied; some still require resource GET/list.
- **Kubernetes writes:** create/dry-run, scale, restart annotation PATCH, YAML PATCH, delete, finalize. Require exact Rust authorization, UID/version baseline where applicable, confirmation/review, and honest accepted/uncertain outcome. A closed confirmation cannot undo a sent request.
- **Privileged/process/network sessions:** Node helper-Pod shell, drain/cordon command, Pod/Service forwarding. Need separately approved lifecycle, authority, bounded output/connections, and cleanup. They are not header decoration.

Recommended order is message/row targets, safe metadata/diagnostics, associated read-only sections, table/scope usability, then separately approved writes/sessions. Reuse the existing guarded deletion contract for pane action placement; do not relax it to imitate upstream's name-based deletion.

## Acceptance requirements for shared changes

| Change | Owner | Concrete acceptance scenario |
| --- | --- | --- |
| Name/row/message parity | React table/overview wiring and existing Rust detail service | Click background and name; Enter/Space opens correct kind/ns/UID; checkbox and menu never activate; Cluster Message targets affected object while Workloads Message targets Event. |
| Optional URL identity/history | React route schema plus Rust named detail validation | Reload/direct link/back/forward with missing/replaced object; no renderer arbitrary URL/path, wrong session or inferred UID; expected scroll policy specified and tested. |
| Title copy/kind identity | Existing pane header, runtime-compatible clipboard boundary | Same name across Service/Deployment has explicit kind; copy returns only intended identity; denied clipboard is actionable; keyboard/tooltip/focus preserved. |
| Structured metadata | Rust details/projection plus typed IPC and pane components | Large/unsafe annotations and managed fields stay bounded; false/empty absent distinguished; Show is read-only and aria-expanded; switching object/session resets reveal state. |
| Related children/events | Rust relation transport/service; frontend independent sections | Same-name replacement, wrong namespace/UID, per-section forbidden/timeout, oversized children and cancellation cannot attach stale rows or erase valid parent facts. |
| Resize/dismiss/scroll | ResourceInspector and existing shell | 390/800/1440, light/dark, reduced motion, zoom, long labels, pending reads; internal scrolling, visible Close, bounded separator; outside-click policy deliberate; close returns focus. |

These are proposed acceptance requirements, not newly implemented behavior. Executed fixture coverage is recorded in chapter 07; no native or real-cluster result is implied.
