### Summary

- The default table columns largely match Freelens's default visible columns. CPU/Memory **numbers do not have the same denominator semantics**: Iceon shows used / allocatable-or-capacity; Freelens shows usage / Pod requests when Pods are loaded.
- The right inspector is a functioning scoped, cancellable, resizable nonmodal reader, not a full Node detail implementation. It supplies reviewed system/address/taint/capacity facts and condition facts. It lacks labels, annotations, managed fields, provider ID, Node-specific metrics, associated Pods and associated Events.
- The screenshot's terminal, pause, drain, edit and delete icons resolve in source to **Node shell, Cordon/Uncordon, Drain, generic YAML Edit, and generic Delete/Force Finalize**. Only close is present in the Iceon Node header; its additional controls are Refresh and expand/restore. Node deletion exists elsewhere in Iceon, in row context and selected-item actions.
- Cordon, uncordon, drain, Node shell and Node YAML editing are not implemented in Iceon. Their absence is not a broken click handler. Node shell in Freelens is particularly consequential: it creates a privileged host-access Pod in `kube-system`, then attaches to it.
- Concrete behavioral problems to distinguish from absent features: Iceon hides custom `True` Node conditions from the visible table summary, cannot search internal IPs/condition text despite displaying them, and silently excludes resource-capacity keys outside four hardcoded keys without a coverage indication. The first two are reference-behavior discrepancies, not proof of a stated Iceon full-parity promise. Condition duplication in the inspector is a smaller current presentation defect.

## 1. Navigation and inventory

### Menu visibility and routes

**Freelens source:** `packages/core/src/renderer/components/nodes/nodes-sidebar-item.injectable.tsx:18-34` supplies the top-level Nodes item, icon, configured ordering and `isVisible: route.isEnabled`. `packages/core/src/common/front-end-routing/routes/cluster/nodes/nodes-route.injectable.ts:12-23` maps `/nodes` to core resource `nodes`. Visibility reads the hosted cluster's `resourcesToShow`, not an action-level write grant (`packages/core/src/renderer/cluster-frame-context/should-show-resource.injectable.ts:15-27`). That set is computed from known resources and namespace list permission predicates, returning no resources when there are no allowed namespaces (`packages/core/src/main/cluster/cluster-connection.injectable.ts:627-640`). Thus “menu visible” must not be equated with patch/delete/Pod-create authorization.

**Iceon source:** `src/app/cluster/navigation.ts:69` defines Nodes in the existing workspace. At the initial baseline, `src/app/cluster/PermissionProvider.tsx:141-152` derived a Node LIST check and hid the destination only for known denial. Concurrent changes observed later at `PermissionProvider.tsx:51-54,106-124,158-167` add navigation-specific visibility: initially unobserved cluster-scoped destinations are hidden, known denial is retained through renewal, and first unknown may expose a destination. This presentation cache is not an authorization grant; see [validation](07-validation.md). `src/app/cluster/PermissionGate.tsx:8-14` renders loading/denied/unverified states and permits an explicitly requested read when authorization is unknown. The Node detail engine validates scope/session/credentials and relies on the actual Kubernetes GET for final read authorization (`src-tauri/src/connection/details.rs:73-102,129-184`); unlike deletion, this path does not call `require_permissions` itself. Do not claim every helper has identical permission preflight.

## 3. Exact action semantics, confirmation, cancellation and authorization

### Freelens Node-specific actions

`packages/core/src/renderer/components/node-pod-menu/node-pod-menu-items/node-menu.injectable.ts:8-18` registers Node/v1 with `enabled = true`; `packages/core/src/renderer/components/kube-object-menu/kube-object-menu-items.injectable.ts:22-31` filters by kind/version/enabled and sorts. The Node-specific menu performs no per-action SSAR/RBAC visibility check. Generic edit/delete visibility is based on store capability/props, **not** proof of user authorization (`packages/core/src/renderer/components/kube-object-menu/kube-object-menu.tsx:203-208`). Kubernetes still enforces actual API permissions. Extensions can change context menus via `onContextMenuOpen` at 286-289, so this is the built-in baseline, not all possible extension behavior.

| Action | Source-confirmed payload and effects | Confirmation / cancellation |
| --- | --- | --- |
| Shell | Creates terminal tab `{title: Node: <name>, node: <name>}`, then hides details. `packages/core/src/renderer/components/node-pod-menu/node-menu.tsx:53-59`. | No pre-shell confirmation here. Closing details is not shell cancellation. Terminal lifecycle owns shell cleanup. |
| Cordon | Sends `<kubectlPath> cordon <nodeName>` where path is configured preference or `kubectl`. `packages/core/src/renderer/components/node-pod-menu/node-menu.tsx:43-67`. | No confirmation. New terminal, Enter emitted; hides details when command dispatch resolves, not when kubectl exits. |
| Uncordon | Same with `uncordon`, offered instead of Cordon when unschedulable. Same source. | No confirmation. No UID/resourceVersion guard in this command string. |
| Drain | Exact command `<kubectlPath> drain <nodeName> --delete-emptydir-data --ignore-daemonsets --force`. `packages/core/src/renderer/components/node-pod-menu/node-menu.tsx:69-81`. Flags are fixed, not a drain options form. | Confirm prompt names Node; OK “Drain Node” sends command. Default Cancel is no-op and closes. After dispatch this dialog cannot undo cordon/evictions/deletions. `sendToTerminal` returns no promise to OK at 46-51, so dialog is not tracking drain completion. |

Dispatch details: `packages/core/src/renderer/components/dock/terminal/send-command.injectable.ts:48-77` creates a terminal when no tabId, waits for terminal/readiness, times out readiness wait after ten seconds with a notification, appends carriage return and writes STDIN. `newTab` is deprecated/ignored, inferred from missing tabId (25-33). No HTTP Node PATCH/eviction body exists in this menu; effects are delegated to kubectl. Do not reinterpret `--force` as `--disable-eviction`: no such flag is supplied. Pod eviction policy, PDB errors, and drain partial progress are kubectl/server outcomes, not a bespoke rollback implementation. Cancellation before confirmation prevents dispatch; after dispatch, terminal interruption is a separate process action, not an atomic undo or reliable drain completion signal.

**Shell privilege and cleanup:** `packages/core/src/main/shell-session/node-shell-session/node-shell-session.ts:62-129,132-247` gets Node OS, creates `node-shell-<uuid>` in `kube-system`, fixes `nodeName`, Never restart, zero termination grace, hostPID/hostIPC/hostNetwork, Exists toleration, system-node-critical priority, interactive tty, configured image/pull secret. Linux uses privileged `nsenter` into PID 1 and bash (Bottlerocket admin special case); Windows uses privileged HostProcess as SYSTEM and PowerShell. It then invokes owned kubectl attach. The abort cleanup waits for the creation promise to settle before deleting the Pod, avoids create/delete races, catches cleanup failure, and waiting owns abort/watch/timer teardown (`packages/core/src/main/shell-session/node-shell-session/node-shell-session.ts:71-119,255-310`). Required API/admission authority therefore extends beyond Node GET to helper Pod create/watch/delete and Pod attach in `kube-system`; Pod security admission can still reject this. No Node shell was executed by this audit.

### Freelens generic edit and delete

- **Edit:** closes inspector and opens generic edit-resource dock tab; no confirmation dialog on entry (`packages/core/src/renderer/components/kube-object-menu/kube-object-menu.tsx:268-282`). Editor loads current resource and builds YAML, with optional Managed Fields and key sorting (`packages/core/src/renderer/components/dock/edit-resource/view.tsx:27-65`; `packages/core/src/renderer/components/dock/edit-resource/edit-resource-model/edit-resource-model.injectable.tsx:330-399`). For Node/non-Pod saves, diff is JSON Patch, not whole-object PUT, server-side apply, or dry-run (`packages/core/src/renderer/components/dock/edit-resource/edit-resource-model/edit-resource-model.injectable.tsx:118-127,413-446`). It adds `freelens.app/resource-version` annotation when saving (`packages/core/src/renderer/components/dock/edit-resource/edit-resource-model/edit-resource-model.injectable.tsx:161-190,425-427`). Request sets JSON patch content type (`packages/core/src/renderer/components/dock/edit-resource/edit-resource-model/request-patch-kube-resource.injectable.ts:33-55`). Save reports success/error; Save & Close closes only for successful result. Cancel closes tab, does not undo an already submitted PATCH; no abort mechanism is passed from InfoPanel to save (`packages/core/src/renderer/components/dock/info-panel.tsx:89-123,150-185`). Do not claim preview/dry-run/second confirmation or optimistic UID preconditions on this path.
- **Delete:** regular Node gets Delete; terminating Node with finalizers gets **Force Finalize**, not Pod-specific Force Delete (`packages/core/src/renderer/components/kube-object-menu/kube-object-menu.tsx:163-177`). Confirmation names kind/name and cluster; OK hides details then awaits deletion service (`packages/core/src/renderer/components/kube-object-menu/kube-object-menu.tsx:102-113,246-264`). Normal mode calls `store.remove`, which deletes by name/namespace and clears selection; API defaults background propagation in query, without explicit DeleteOptions or UID/resourceVersion preconditions in that call (`packages/core/src/renderer/components/kube-object-menu/kube-object-delete-service.injectable.ts:23-55`; `packages/core/src/common/k8s-api/kube-object.store.ts:461-468`; `packages/utility-features/kube-api/src/kube-api.ts:782-802`). Force Finalize merge-patches `{metadata:{finalizers:[]}}`; it is not another normal DELETE.
- Shared confirmation defaults Cancel to no-op. OK waits callback, catches failure notification, then closes even on failure. Cancel closes state and does not abort an in-flight operation (`packages/core/src/renderer/components/confirm-dialog/confirm-dialog.tsx:49-55,72-118,127-155`). UI confirmation is not rollback. For drain, callback does not return terminal dispatch promise, an additional distinction from generic awaited deletion.

### Iceon current operations and safeguards

Node row actions are **Details and Delete only**, not Shell/Edit: `src/app/cluster/RowContextMenu.tsx:110-139`. Shared native row popup is invoked by the row plugin, independent of checkbox selection; permissions are reviewed for exact target and open ownership invalidated using authorization fingerprint. Details is disabled for known get denial; delete requires allowed get+delete, live inventory and UID/resourceVersion. Unknown write permission never enables deletion.

`src/app/cluster/ResourceDelete.tsx:22-45,48-145` provides exact-target confirmation, cluster ID/name/context, irreversible/dependents warning, normal grace/finalizer wording, double-submit guard, sequential per-target IPC, progress/accepted-vs-deleted results, and refresh. Cancel/Escape before submission does not delete; Stop during work cancels the active lane, prevents remaining submissions and warns a request may already have reached Kubernetes. Closing/disposal does not roll back. Failure does not claim a resource is gone.

Rust owner `src-tauri/src/connection/delete.rs:120-141,225-259` requires get+delete permission, performs named preflight GET, validates UID/resourceVersion, then DELETE with `{apiVersion:v1, kind:DeleteOptions, propagationPolicy:Background, preconditions:{uid,resourceVersion}}`. It does **not** set grace zero or strip finalizers. This is a safer intentional alternative to upstream's ordinary delete and not parity with Force Finalize. Thin command/adapters preserve session/read identity; no renderer kubectl is appropriate.

Inspector disposal cancels exact detail reads; Rust high-water tombstones prevent old cancel/read from affecting newer work, latest read cancels previous, session/credential validation and bounded worker ownership apply (`src/app/cluster/ResourceInspector.tsx:201-220`; `src/app/cluster/detailApi.ts:129-142`; `src-tauri/src/connection/details.rs:104-191`). Named object projection checks kind/apiVersion/name/namespace/UID before display (`src-tauri/src/connection/details.rs:198-246`). Missing/replaced/errors and retained stale facts are visible, not silently reinterpreted as current (`src/app/cluster/ResourceInspector.tsx:217-243`). Width resize, keyboard separator, expand, guarded Escape and focus restoration are intentional shell alternatives (`src/app/cluster/ResourceInspector.tsx:44-48,115-175`), not evidence of native OS verification.
