# Namespaces, standalone Events, and Custom Resources

Source-only extension to [shared inspector](06-shared-inspector.md) and [earlier validation](07-validation.md); new validation belongs to [expanded validation](15-expanded-validation.md). Reference: local Freelens `cd07118f843c4a69f937a319a37a7c12ef2c92d8`, `v1.10.3-533-gcd07118f`. Iceon HEAD is `e71baf2d51d2be391485d52dd837f428dc8d21aa`, with concurrent dirty-tree implementation changes. Citations describe inspected working-tree files, not an immutable release. Paths beginning `packages/` refer to Freelens; `src/` and `src-tauri/` refer to Iceon. No upstream source was changed or copied; no app, cluster operation, test, credential read, or dependency installation was performed for this extension.

This chapter audits **four distinct panes**. Standalone Events is not the Cluster/Workloads overview Event presentation audited in 01. A metadata inventory is not an instance inspector, and generic CRD operations are not dynamic-CR operations. Shared missing metadata/history/associated Events and nonmodal Astryx mechanics remain as classified in 06.

## Namespaces

**Reference list and gestures.** `packages/core/src/renderer/components/namespaces/route.tsx:43-109` defines configurable **Name, Labels, Age, Status**, searchable metadata/status, sortable fields, subscribed store, selected-item deletion and Add Namespace. Labels are values/badges, not just a count; names can have a conditional Subnamespace badge. Shared row activation opens details. The dedicated Add dialog lowercases/validates a namespace name and invokes `namespaceStore.create({ name })`, with failure notification (`namespaces/add-dialog/dialog.tsx:60-94`). Namespace deletion routes through `request-delete-namespace.injectable.ts`, which is a distinct namespace workflow, not proof of ordinary resource-deletion equivalence.

**Reference detail.** Shared metadata precedes **Status, Resource Quotas, Limit Ranges**. Child names link to their exact details; subscriptions for quotas/ranges are disposed on unmount (`packages/core/src/renderer/components/namespaces/namespace-details.tsx:49-69,85-114`). These are collections in the selected namespace, not namespace-wide aggregate counts. Shared metadata/edit/delete/finalizer behavior is subject to available store operations and the common menu, not an unconditional authorization promise.

**Iceon actual path.** The active route uses `ResourceTablePage`, not the older two-column Namespaces branch of `ClusterResources`: `src/app/cluster/ClusterWorkspacePage.tsx:46-48,97-101`. `src/app/cluster/resourceViews.ts:218-220` plus `ResourceTablePage.tsx:59-73` produce **Name, Label Count, Age, Status** (with selection controls), no Namespace column on this cluster-scoped list. Name opens `{kind: namespaces, namespace: null, name, uid}`; a blank row is not the Name button. Labels are intentionally counted in Rust (`src-tauri/src/connection/resources.rs:396-402`), not rendered as full metadata. `src-tauri/src/connection/transport.rs:379` fixes the core-v1 namespace endpoint. The detail contains the common reviewed identity/columns and **Namespace lifecycle / Phase** (`connection/detail_facts.rs:728`), not quota/range collections.

**Actions, state and authority.** Table creation is the generic YAML metadata scaffold for `v1/Namespace` (`src/app/cluster/resourceViews.ts:299`), with dry-run/confirmation; it is not the upstream name-only wizard. `ResourceActions.tsx:15-32` wires create/delete and permission-derived read-only/unverified notices. Existing generic deletion preserves UID/resourceVersion preconditions and normal finalizers (`src-tauri/src/connection/delete.rs`); no namespace-specific finalize or generic non-Pod edit appears in this pane. The shared table owns bounded reads, search/status filtering, continuation, stale/error/empty states and exact read cancellation; the shared inspector owns independent named GET/disposal (06). A successful list does not prove GET/create/delete access. Namespace child reads would additionally require list/get on quotas and limit ranges. Do not substitute an empty collection for forbidden.

| Gap / deliberate difference | Rust owner and UI states required | Acceptance requirement (proposed, not executed) |
| --- | --- | --- |
| Label values and Subnamespace indicator absent | `connection/resources.rs` / `detail_facts.rs`: reviewed bounded labels and explicitly supported hierarchy metadata; retain count-only policy unless product approval changes it | Many/unsafe labels, no labels and unavailable hierarchy render distinctly; no imported metadata is called connectivity or health. |
| Quota and LimitRange linked sections missing | `connection/details.rs` plus transport: namespace-bound independent child reads; loading/empty/denied/stale/partial per section | Select same-named namespace after UID replacement; old children never attach; each link opens exact child; close cancels pending reads. |
| Name-only creation differs; YAML editing/finalization missing | `connection/create.rs`, `delete.rs` and a separately approved edit/finalize service; review/forbidden/conflict/accepted/uncertain states | Generic create submits nothing on open, requires dry-run and confirmation; terminating namespace is not force-finalized by ordinary Delete; explicit finalize must disclose destructive effect. |

## Standalone Events

**Reference list.** `packages/core/src/renderer/components/events/events.tsx:79-91,149-196,198-221` defines **Type, Message, Namespace, Involved Object, Source, Count, Age, Last Seen**; default age sorting, nonselectable rows, virtual standalone list, limit hint, metadata/message/source/involved-name search. Message uses warning styling and tooltip; row opens the Event through shared details, while Involved Object stops propagation and opens the API-manager-resolved target. Namespace badge changes namespace filter rather than opening a Namespace inspector. Compact overview behavior is a different mode and is not being counted here.

**Reference detail.** `packages/core/src/renderer/components/events/event-details.tsx:48-83` shows **Message, Reason, Source, First seen, Last seen, Count, Type**, then Involved object table **Name (linked), Namespace, Kind, Field Path**. First/last use relative plus absolute timestamp component. Its typed lookup is not evidence that a name-only link validates UID replacement.

**Iceon list and detail.** `src/app/cluster/resourceViews.ts:222-227` and `ResourceTablePage.tsx:59-73` actually show **Name, Namespace, Type, Reason, Involved Object, Count, Age, Status**, not Message/Source/Last Seen. Name opens Event detail; Namespace opens namespace detail; Involved Object triggers backend relation resolution, not display-text parsing. Detail renders **all projected column facts**, including bounded `message`, `source`, `lastSeen` and `occurrenceTime`, even when they are not table columns (`src/app/cluster/ResourceInspector.tsx:235-237`), plus **Event summary / Type, Reason, Count, First timestamp, Last timestamp, Reporting controller** (`src-tauri/src/connection/detail_facts.rs:729-739`). Thus Message/Source are **present as generic facts**, not missing detail data; dedicated timestamp labels/relative formatting and the involved-object Field Path table remain different.

**Projection precision.** `src-tauri/src/connection/resources.rs:785-837` projects type/reason/message; count prefers `series.count` then `count`; lastSeen prefers `series.lastObservedTime`, `lastTimestamp`, `eventTime`, `firstTimestamp`; occurrenceTime prefers `eventTime` then `firstTimestamp`. Source prefers nonempty `reportingComponent`, then `source.component`: this differs from the detail's separate `reportingController` field. Creation-based Age is not Last Seen. `resources.rs:846-854` strips controls/bidi controls and truncates strings at **256 UTF-8 bytes**, without a per-message truncation flag/full-text retrieval. Bounded Event text is **not guaranteed secret-free**, and omitted table columns must not be described as absent backend data. Exact related targets in `connection/details.rs:464-498` require allowlisted apiVersion/kind, valid name and UID, consistent namespace, and agreement if both `involvedObject` and `regarding` exist. Unknown custom kinds receive no invented link; a replaced UID fails rather than opening the newer object as the old event target.

**Lifecycle/actions/permissions.** The standalone route is the generic paged polling table and named detail GET, not an Event watch. Generic create/delete scaffolding exists for the allowlisted `v1/Event` kind (`resourceViews.ts:332`, `ResourceActions.tsx:15-32`); upstream's nonselectable Event list is therefore **not** evidence that Iceon is read-only. No Event-specific editor/finalize control exists. Namespace changes dispose old scope, detail refresh may retain stale facts, and server list/get/write denial stays separate. Event-to-target navigation also needs target GET; denied/missing/unknown target is not an empty successful Event read.

| Gap / deliberate difference | Rust owner and UI states required | Acceptance requirement (proposed) |
| --- | --- | --- |
| Missing Message/Source/Last Seen table columns; generic bounded detail instead of dedicated diagnostics | `connection/resources.rs`, `detail_facts.rs`, typed DTO: unify documented timestamp/source semantics; visible bounded/truncated/unavailable state | Legacy timestamp, series-only, invalid dates, missing count, multibyte 256-byte boundary and controller/component variants; no secret-free or full-text claim; unknown stays N/A. |
| Missing involved Field Path/full identity presentation | `connection/details.rs`: bounded field path and reviewed identity, never arbitrary API URL | Conflicting involvedObject/regarding, wrong namespace, absent UID, dynamic kind, same-name replaced target; no guessed navigation or cross-session facts. |
| Namespace filter gesture and nonselectable upstream differ | Existing Rust scoped inventory/create/delete services; React must keep mutation and navigation targets independent | Namespace navigation versus filter is explicit; checkbox/menu never opens Event; create/delete denied or uncertain cannot become a successful read badge. |

## CustomResourceDefinition definitions

**Reference.** `packages/core/src/renderer/components/custom-resource-definitions/view.tsx:119-185` defines **Resource, Group, Version, Short Names, Scope, Age**, configurable sort/search and multiselect Group URL filter. Resource is a stop-propagating **instance-route link**, distinct from row-to-definition drawer. `custom-resource-definitions/details.tsx:54-145` shows **Group; Versions (preferred star); Stored Versions; Scope; Resource link; Conversion (read-only text); Conditions; Names table (plural, singular, kind, listKind, shortNames)**. Additional Printer Columns appear only when present (**Name, Type, JSON Path**); Validation appears only when provided, in a read-only editor. `packages/kube-object/src/specifics/custom-resource-definition.ts:204-223,285-292` selects served storage first, otherwise a served version or storage fallback; printer columns/schema come from that selected version, Age columns are excluded, and list mode excludes positive priority columns while details include them. This is a selected-version schema/column-definition view, not an all-version schema browser or evaluation of arbitrary JSONPath in Iceon's renderer contract.

**Iceon.** `src/app/cluster/resourceViews.ts:283-288` adds shared **Name, Age, Status** around **Resource, Group, Versions, Short Names, Scope**. Resource here is a scalar kind, not that upstream instance-route link (`ResourceTablePage.tsx:47-73`). The Group filter is the bounded Rust table filter, not upstream multiselect URL persistence. `src-tauri/src/connection/resources.rs:317-331` projects group/scope/kind/plural, at most the first **12 version names**, and bounded short names; this is not the complete served/preferred/schema inventory. Detail **Custom resource definition** includes Group, Scope, Kind, Plural, Conversion strategy; **Versions** rows include Name/Served/Storage; **Stored versions** lists status versions (`detail_facts.rs:700-727`). Shared condition projection exists, but full conversion payload, singular/listKind, schema validation editor and additional-printer-column schema table are absent.

**Actions/permissions/lifecycle.** Definition Name opens typed fixed-kind detail. Generic CRD YAML creation (`resourceViews.ts:338`) and confirmed deletion apply to `apiextensions.k8s.io/v1/CustomResourceDefinition`, **not its instances**. Non-Pod YAML edit and CRD finalize are absent. The common upstream menu conditionally offers edit and generic delete/finalize modes (`packages/core/src/renderer/components/kube-object-menu/kube-object-menu.tsx:163-175,207-279`); they are common-kind capabilities, not evidence of a specialized CR editor. CRD list/get/delete permissions are separate from the dynamic resource's permissions. Discovery failures must not imply zero definitions, and deleting a definition has instance consequences that a future confirmation should explain. Current definition read cancellation/staleness follows 06 and the shared inventory contract.

| Gap / deliberate difference | Rust owner and UI states required | Acceptance requirement (proposed) |
| --- | --- | --- |
| Preferred/per-version schemas, printer columns, names and conversion missing/partial | `connection/detail_facts.rs` plus bounded CRD-specific DTO; absent/partial/oversize/invalid-schema/denied states | Multiple served/storage versions, >12 names, priority columns, empty schema and oversized conversion: never label joined/truncated names complete or a storage flag preferred without a declared policy. |
| Resource-to-instance gesture missing from definition cells/detail | `connection/custom_resources.rs` identity authority; React selected-definition route | Click Resource and Name lead to different intended surfaces; selected definition name+UID revalidated; missing/replaced definition cannot silently use a neighboring group/kind. |
| Edit/finalize absent; generic-kind create/delete present | Existing create/delete owners; separately approved schema-edit/finalize service with authorization/UID/version checks | CRD operations cannot be submitted as CR-instance mutations; schema change conflict and deletion consequences are confirmed, cancellation never claims rollback. |

## Dynamic custom-resource instances

**Reference.** `packages/core/src/renderer/components/custom-resources/view.tsx:71-107,118-181` resolves group/name to CRD preferred version, or API-discovery fallback when CRD listing is unavailable; selected API base keys the list. Fields are **Name, conditional Namespace, priority-filtered additional printer columns, Age**. JSONPath values are formatted; namespace badge filters scope; missing/unserved preferred version gets a specific failure message. Detail shows all CRD printer values (arrays recursively; objects as JSON; booleans distinctly) and Conditions; without a definition, no invented columns (`custom-resources/details.tsx:31-62,100-107`). Shared metadata/menu is separate. Generic editing/deletion/finalizer modes depend on registered store support; the inspected instance view does not itself add a CR-specific create wizard, and generic global resource creation must not be mislabeled one.

**Iceon inventory is not an instance pane.** `src/app/cluster/CustomResourceTable.tsx:15-30,49-69` resolves the selected definition by name in the current cluster/session snapshot, keys scope by definition UID, then displays **Name, conditional Namespace, Created, Labels (count)**. Names are plain Text: **no instance click/detail/YAML**, additional JSONPath columns, condition inspection, selection, create/edit/delete/finalize, or per-instance context menu. Static-kind generic actions do not extend to arbitrary CRs. `CustomResourcesProvider.tsx:62-90` bounds paged discovery with timeout, duplicate/replaced identity and repeated-token detection; failure/partial discovery can leave a selected definition unavailable rather than claiming it does not exist cluster-wide.

**Backend identity and redaction.** `src-tauri/src/connection/custom_resources.rs:281-338` freshly GETs the selected CRD before each instance list. `:353-416` checks exact CRD apiVersion/kind/name/**UID**, validates group/plural/kind, requires Established=True, chooses **served+storage first, else first served** (not an arbitrary user-supplied version/path). `:418-438` builds `/apis/<group>/<version>[/namespaces/<ns>]/<plural>?limit=100[&continue=…]`; All namespaces is a real unscoped collection read, not client-side union/filter. Cluster-scoped definitions reject namespace input. `:440-484` requires PartialObjectMetadataList, at most 100 rows, exact namespace consistency, UID/name validation and no duplicate scoped names. Only identity, creation timestamp and label count leave Rust; no spec/status/annotations/label values/schema-driven payload projection. Metadata-only negotiation is not a claim Kubernetes never returns sensitive metadata, and no silent full-object renderer fallback is justified.

**Lifecycle/permission limits.** `CustomResourceTable.tsx:40-58` polls first page at 10 seconds, pauses automatic refresh beyond first page, cancels exact old request and ignores disposed replies on namespace/definition/session changes. Failed refresh retains the page with an error; partial pages are labeled and Next/Previous registered. Discovery is gated on static CRD-list permission (`ClusterWorkspacePage.tsx:91-95`); dynamic LIST/CRD GET remain server-enforced. There is no API-discovery-only fallback when CRDs cannot be listed, and the static permission gate does not prove dynamic-kind authorization. The definition's server-selected version returned by Rust is not a displayed version-selection UI.

| Gap / deliberate difference | Rust owner and UI states required | Acceptance requirement (proposed) |
| --- | --- | --- |
| No instance inspector or printer-column/status payload | `connection/custom_resources.rs`: separately reviewed CR-specific named GET/DTO/redaction policy; loading/metadata-only/denied/partial/replaced states | Secret-like custom fields, malicious JSONPath/schema, duplicate names across namespaces, same definition name/new UID: no arbitrary full JSON or stale payload crosses IPC. |
| No discovery-only fallback / explicit version experience | Rust API discovery and definition service, not renderer URL construction; CRD-denied versus kind-list-denied states | Allowed kind LIST with denied CRD LIST remains honestly unsupported today; any future fallback validates group/version/plural and never assumes a schema or namespace scope. |
| No dynamic create/edit/delete/finalize | New CR-specific mutation owner, not widening static `ResourceKind`; dry-run/review/conflict/accepted/uncertain lifecycle | Wrong definition UID, changed served version, forbidden writes and cancel-after-send cannot mutate a different kind or imply rollback; removing finalizers requires distinct approval. |
