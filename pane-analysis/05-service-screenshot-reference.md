## Findings that affect the implementation boundary

1. **Service details are currently a bounded Rust fact projection, not the screenshot's complete inspector.** Iceon already exposes policy fields, selector, address arrays, numeric/string target ports and basic ingress IP/hostname. It does not expose appProtocol, ingress IP Mode, associated EndpointSlices, associated events, managed-fields expansion, or generic Service edit/finalize. Several omissions are deliberate reviewed-metadata boundaries rather than a missing React label.
2. **Pod forwarding exists; Service forwarding does not.** `PodForwardRequest` has a Pod identity and UID, not a resource-kind discriminator or Service resolution contract. A Service name cannot safely be passed to the Pod command. The existing Rust listener and cancellation machinery are reusable capabilities, not evidence of Service integration.
3. **Freelens forwards through a main-process bundled `kubectl` subprocess.** It does not implement Service forwarding by opening a Service ClusterIP in the renderer, and its application transport is a local JSON HTTP API, not a Tauri IPC command. Kubernetes port resolution is delegated to `kubectl port-forward service/<name> <local>:<servicePort>`.
4. **The upstream “External IPs” label hides multiple origins.** `getExternalIps()` is a precedence-based projection, not a union: ingress entries win whenever `status.loadBalancer.ingress` exists, otherwise `spec.externalIPs` is used. The detail and list add `externalName` only when that result is empty. Iceon must preserve spec and status origin instead of relabeling one as the other.
5. **Closing the upstream Service drawer is not stopping its forwards.** It disposes subscriptions/reactions only. Iceon's lifecycle must explicitly define forward ownership and cancellation; do not infer process cleanup from drawer unmount.
6. **Service health is not established by those fields.** Freelens labels non-LoadBalancer Services Active unconditionally; its LoadBalancer status depends on external-address array length. Iceon's Service inventory returns Unknown. Neither a selector nor a running local listener proves ready backends or end-to-end reachability.

## List workflow: exact columns, search, sort, activation

FL `packages/core/src/renderer/components/network-services/services.tsx:57-96` specifies configurable `network_services` columns in this order:

**Name | Namespace | Type | Cluster IP | External IP | Ports | Age | Status**, plus shared checkbox/menu affordances. External IP is singular in the table heading, plural in details. Columns can be configured, so a screenshot is not proof all columns were enabled.

Sort callbacks are name, namespace, first declared numeric Service port (not minimum across all ports), scalar clusterIP, type, negative creation timestamp, and status. External IP has no sort callback. The Service page does not set a default sort. Shared table uses persisted table-specific sorting, and returns unsorted raw items if sortBy/orderBy is missing: `packages/core/src/renderer/components/table/table.tsx:161-164,203-220`; persistence is `packages/core/src/renderer/components/table/table-model/table-model.ts:20-29`. Do not claim a hardcoded alphabetical initial order.

Search is an OR across base search fields (name, namespace, UID, metadata labels), joined selector strings, and joined ServicePort strings. It does **not** explicitly index type, IPs, annotations, affinity, events or endpoint addresses. See services:71-75; `packages/kube-object/src/kube-object.ts:217-219`; `packages/core/src/renderer/components/item-object-list/list-layout.tsx:264-275`. Matching is case-insensitive substring matching, additionally stripping dashes/underscores from candidate text while leaving query separators literal (`packages/core/src/renderer/components/item-object-list/search-matcher.ts:8-32`). List `ServicePort.toString()` is `port[:nodePort-or-target]/protocol` (FL Service model:31-40), not the richer detail arrow string and not appProtocol-aware.

The list's shared namespace selector filters contextual store items (`packages/core/src/renderer/components/kube-object-list-layout/kube-object-list-layout.tsx:240-261`). Clicking its namespace badge sets the **global namespace filter** without opening the Service (`packages/core/src/renderer/components/namespaces/namespace-select-badge.tsx:29-49`). In contrast, the detail namespace link opens Namespace details (`packages/core/src/renderer/components/kube-object-link/link-to-namespace.tsx:26-44`).

Row click toggles details by selfLink; checkbox clicks select without activation; menu clicks stop propagation (`packages/core/src/renderer/components/item-object-list/content.tsx:343-385`; kube-object-list-layout:273-280). Right-click opens the same registered row menu at the cursor, suppresses the native context menu/propagation and closes other row menus (kube-object-list-layout:205-235). These shared behaviors do not imply Service-specific restart/scale/logs actions.

Upstream list status is `Active` for every non-LoadBalancer Service, otherwise Active when `getExternalIps().length > 0`, Pending when zero (FL Service model:150-155). Empty ingress arrays suppress spec externalIPs, and entries without an address can still contribute length. Treat this as an upstream display heuristic, not backend health or a desirable Iceon health guarantee.

IC `src/app/cluster/resourceViews.ts:155-165` defines Service-specific columns Type, Cluster IP, **External IP Count**, Ports, and standalone EndpointSlice columns. `src-tauri/src/connection/resources.rs:729-754` counts spec externalIPs and ingress separately, lists up to twelve numeric ports and returns Unknown. Renaming a count to External IP would be false parity.

## Action chains and side effects

### Managed Fields Show/Hide: read-only presentation

FL metadata filters entries to nonempty string manager and operation, labels manager/operation with optional subresource and a time tooltip, and expands only `fieldsV1` as YAML in a read-only Monaco editor. Keys include manager, operation, apiVersion and subresource. The toggler only flips local open state and mounts children while open: `packages/core/src/renderer/components/drawer/drawer-param-toggler.tsx:23-45`. This does not patch managedFields, transfer ownership or invoke server-side apply. Keep it distinct from the YAML editor's separate Managed Fields display option.

The generic drawer keys detail components by object UID, resetting expanded state on object replacement (`packages/core/src/renderer/components/kube-object-details/kube-object-details.tsx:69-77`). Iceon should preserve this reset and implement keyboard-operable Show/Hide with aria-expanded rather than copying the upstream clickable div.

### Namespace and EndpointSlice navigation

Service mount subscribes to EndpointSlice store and forward-store observation; unmount disposes both (FL service detail:54-64). Association uses `getByOwnerReference(service.apiVersion, kind, name, namespace)` (:80-85). The helper compares namespace and owner apiVersion/kind/name, **not owner UID** (`packages/core/src/common/k8s-api/kube-object.store.ts:169-179`). It does not query the Service's selector or the `kubernetes.io/service-name` label in this code path. Consequently selectorless manually associated slices may not appear, and same-name recreated Services warrant stronger identity handling in Iceon.

The slice table is shown only when matches exist. A row calls `showDetails(endpointSlice.selfLink, false)` (FL slice rows:49-65); it does not start a forward or select a backend Pod. The model joins all endpoint addresses without readiness filtering. Iceon needs a Rust-owned, bounded associated read with identity/provenance rules, per-section failures and explicit navigation references. Merely linking to the all-slices table would not reproduce association.

### Events: separate subscription and object association

The generic event detail registration is enabled for all resources and ordered last (`packages/core/src/renderer/components/kube-object-details/kube-object-detail-items/implementations/kube-event-detail-item.injectable.ts:12-19`). It owns its store subscription and disposal (FL events:53-59), not the Service detail component. Service events are grouped by `involvedObject.uid` matching Service UID (`packages/core/src/renderer/components/events/store.ts:47-71`). They are sorted descending by parsed `lastTimestamp`; missing/invalid values sort as zero, while Last seen is rendered only for truthy timestamp. Empty displays “No events found” (FL events:39-46,74-98). No associated Service event fetch exists in IC `ResourceDetail`; the result contract is item, related references, sections (`src-tauri/src/connection/details.rs:34-44,235-258`). Empty, denied and failed event reads must not collapse into one “No events” message.

### Edit / Delete / Force Finalize / Close

The generic FL toolbar supplies `KubeObjectMenu`, and closing calls hideDetails (generic drawer:54-60). Menu editability/removability follows presence of store patch/remove or overrides, not a demonstrated per-resource RBAC probe (`packages/core/src/renderer/components/kube-object-menu/kube-object-menu.tsx:203-208`). Edit hides the drawer and opens the generic edit-resource tab (:268-281). Save parses YAML, computes a patch against the original draft, resolves selfLink and requests a patch; failures notify without success (`packages/core/src/renderer/components/dock/edit-resource/edit-resource-model/edit-resource-model.injectable.tsx:413-451`). The request uses JSON/selected patch strategy, optional subresource and the corresponding content type, through the Kubernetes JSON API (`packages/core/src/renderer/components/dock/edit-resource/edit-resource-model/request-patch-kube-resource.injectable.ts:28-57`; `packages/core/src/renderer/k8s/api-kube-patch.injectable.ts:18-24`; `packages/core/src/renderer/k8s/api-kube.injectable.ts:26-39`). This is API patching through the application proxy, not `kubectl edit`.

For a **Service**, normal or nonterminating resource => Delete; deletionTimestamp plus nonempty finalizers => **Force Finalize**; terminating without finalizers => Delete. Pod-only force-delete rules do not apply (`packages/core/src/renderer/components/kube-object-menu/kube-object-menu.tsx:163-177,213-263`). Confirmation identifies namespace/name/cluster, then hides details and executes. Delete calls store.remove => API DELETE. Force Finalize calls merge PATCH `{metadata: {finalizers: []}}`; it is not another DELETE and can bypass cleanup obligations (`packages/core/src/renderer/components/kube-object-menu/kube-object-delete-service.injectable.ts:23-55`; `packages/core/src/common/k8s-api/kube-object.store.ts:411-438,461-468`). A visible Finalizers row is not itself this destructive control.

IC has generic resource deletion with UID/resourceVersion baselines and preconditions, normal grace behavior and Background propagation (`src-tauri/src/connection/delete.rs:18-48,227-258`; `src/app/cluster/ResourceDelete.tsx:105,131`). It also has Pod-specific edit/finalization in `src-tauri/src/connection/pods.rs:259-352`. Neither establishes Service edit/finalize. Add no working-looking generic Service toolbar mutation until a Rust-owned safe contract and permission checks exist. Close/refresh/navigation already exist in the inspector and must remain usable when writes are denied.

### Forward: UI → model → local API → main subprocess → browser handoff

1. **Eligibility and display.** FL port row:172-217 shows actions only with a nonempty selector. It does not check TCP vs UDP/SCTP here; selector presence alone is not sufficient capability validation. The row string includes appProtocol, but browser scheme prediction is only `port.name === "https"`, otherwise http (`packages/core/src/renderer/port-forward/port-forward-utils.ts:9-16`). appProtocol is not used to choose that scheme.
2. **Two different triggers.** Clicking the port text attempts add/start and opens a browser directly; clicking Forward… opens the dialog with `openInBrowser: true`. Existing forward button removes/stops it instead (FL port row:101-145,148-168,182-211). Opening details only checks existing state; it does not start forwarding. Busy state adds spinner/waiting styling. Do not copy the inaccessible clickable span or assume this class disables every repeated click.
3. **Dialog model.** `packages/core/src/renderer/port-forward/port-forward-dialog-model/port-forward-dialog-model.ts:24-38` stores item, HTTPS flag, openInBrowser and onClose. Close clears the model; no process stop is implied. `packages/core/src/renderer/port-forward/port-forward-dialog.tsx:49-69,123-185` offers listen-address text (localhost default), local numeric port with 0–65535 attributes and blank “Random”, HTTPS and Open in Browser checkboxes, Start/Modify. Conversion uses `Number(value)`; the input attributes are not evidence of a robust integer/range validator or address allowlist.
4. **Dialog submission.** The address is copied onto the forwarded item; HTTPS becomes protocol http/https; add or modify is awaited; Disabled raises notification; browser opens only if Active and checked. Errors are logged and the dialog closes in finally (`packages/core/src/renderer/port-forward/port-forward-dialog.tsx:75-120`). Closing after error is an upstream behavior, not a recommended loss of actionable error context.
5. **Renderer store.** `packages/core/src/renderer/port-forward/port-forward-store/port-forward-store.ts:108-159,165-189,206-289` keys by kind/name/namespace/remote port (:324-329), adds/start/modifies/stops, stores Active/Disabled and actual local port. Modify of active work first stops it (ignoring stop failure) and restarts. Stop sends DELETE and waits for local port free; remove can still drop the saved row after stop error. Watch/persistence is :39-81, including automatic restart of saved Active entries. These persistence/restart semantics are not an Iceon requirement.
6. **Transport, not a pretend Tauri IPC.** The store POST/DELETE and active-status GET go to `/pods/port-forward/{namespace}/{kind}/{name}` despite supporting `kind: "service"` (store:220-225,270-285; `packages/core/src/renderer/port-forward/port-forward-store/request-active-port-forward.injectable.ts:16-42`). They use the local JSON API configuration at `packages/core/src/common/k8s-api/api-base.injectable.ts:14-35`. GET returns a port/null, which the renderer maps to Active/Disabled; it is not a reachability probe. Iceon must replace this boundary with typed Rust IPC, not reproduce a Node server.
7. **Main route.** `packages/core/src/main/routes/port-forward/start-port-forward-route.injectable.ts:22-89` scopes to routed cluster, converts query ports, reuses existing cluster/kind/namespace/name/remote-port match, normalizes an out-of-range desired local port to zero, obtains proxy kubeconfig paths and starts the process. It does not explicitly reject fractional local ports; do not describe this as strict validation. GET/DELETE use the same identity (`packages/core/src/main/routes/port-forward/get-current-port-forward-route.injectable.ts:16-37`; `packages/core/src/main/routes/port-forward/stop-current-port-forward-route.injectable.ts:19-51`).
8. **Actual subprocess semantics.** `packages/core/src/main/routes/port-forward/functionality/create-port-forward.injectable.ts:22-31` selects **bundled kubectl**. `packages/core/src/main/routes/port-forward/functionality/port-forward.ts:74-109` spawns an argv array with proxy kubeconfig/cache paths, `port-forward --address <address> -n <namespace> service/<name> <local>:<service-port>`, and proxy credential environment. Kubectl performs Service-to-Pod/target-port selection; this main implementation contains no explicit Service selector/EndpointSlice resolution algorithm. It parses “Forwarding from … ->” stdout and waits up to 15 seconds for the chosen port on the first listen address (:107-126). A local listener being bound is not a successful application HTTP request.
9. **Stop/error/cleanup.** Process exit removes its registry entry (:94-101); failure of the waitUntilUsed probe kills the process; stop calls process.kill (:123-132). The stdout parser itself has a separate default 15-second timeout and removes data/abort listeners and its timer on completion/timeout (`packages/core/src/main/utils/get-port-from-stream.injectable.ts:40-83`); this caller passes no AbortSignal. Parsing/spawn failure handling must not be overstated: exceptions before the bind probe's try/catch are not covered by its kill branch. Parser cleanup is not subprocess cleanup. Drawer disposal only removes reactions (FL service detail:62-64), and saved forward initialization can restart work later. No guaranteed close-drawer/disconnect/shutdown cleanup can be claimed from this chain alone.
10. **Browser.** `packages/core/src/renderer/port-forward/open-port-forward.injectable.ts:17-35` builds protocol + first listen address + actual local port and catches OS handoff failures with notification. `packages/core/src/common/utils/open-link-in-browser.injectable.ts:10-24` validates http/https then calls Electron shell.openExternal. This is separate from the external-address anchors: FL service detail:42-49 chooses https when any Service port is 443, otherwise http for 80, and :229-239 builds an address URL without an explicit port. Neither route should become renderer window.open or unrestricted Tauri opener access.

## Iceon ownership and capability gap

### Existing Rust capabilities to preserve

- **Inventory, facts and relations:** `src-tauri/src/connection/resources.rs`, `detail_facts.rs`, `details.rs`. Service facts already preserve spec externalIPs separately from ingress IP/hostname. `details.rs:260-285` adds namespace references; there is no Service-associated list in the inspected response. Facts are bounded: twelve sections, 32 facts/section, twelve collection items and safe scalar/total limits (`detail_facts.rs:5-9,22-32,69-128`); partial omissions produce a Coverage section (:174-203). A new rich projection must retain explicit coverage, not silently flatten unlimited nested status/managed fields into strings.
- **Inspector presentation:** `src/app/cluster/ResourceInspector.tsx:201-243` reads/cancels scoped details, shows loading/error/retained-stale state, namespace/other typed relations and fact sections. It explicitly says raw objects/credentials/configuration are not exposed. Service metadata expansion requires Rust review, not a renderer raw-object escape hatch.

A Service-aware forward contract must resolve `spec.ports` by stable selection, accept named targetPort only after backend Pod resolution, default missing transport carefully, reject UDP/SCTP forwarding, handle no selector, no eligible Pod, headless and ExternalName cases explicitly, and retain both Service and chosen Pod UIDs. No automatic persisted-forward restart without an approved lifecycle contract.

View disposal, scope change, disconnect and shutdown need an explicit owner for every associated read/watch/forward and bounded cancellation/cleanup. If forwards are intentionally transferred from an inspector to a persistent workspace session, ownership transfer must be visible and tested, not an accidental survival of unmount. Browser opening and local networking remain Rust responsibilities.

## Audit result

The screenshot is a useful field-and-action inventory, not proof of parity. The highest-priority gaps are typed Service metadata/appProtocol/ingress status, independently scoped associated slices/events, safe Service mutation integration and a real Service-aware Rust forwarding contract. Existing Pod forwarding, generic deletion, namespace navigation and bounded detail projection should be reused without claiming they already implement those Service workflows. No application code was changed or tests executed for this document; fixture verification belongs to the implementation task.
