### Metrics and Events

**Metrics:** upstream Pod time-range registration is `F/kube-object-details/kube-object-detail-items/metrics/pod-details-pod-metrics.injectable.ts:13-20`; requests explicitly ask CPU/memory/fs usage+writes+reads/network receive+transmit with Pod namespace and start/end/range (`F/workloads-pods/metrics.injectable.ts:16-26`). Charts CPU, Memory, Network, Filesystem, empty→NoMetrics (`pod-charts.tsx:33-113`). Per-container charts are only rendered for regular containers when Container metrics enabled (`pod-details-container.tsx:109-124,223-224`); container charts include CPU/memory Usage/Requests/Limits and filesystem usage/writes/reads (`container-charts.tsx:45-116`). **Iceon has no Pod table CPU/memory or Pod/container detail history**; current Node metrics service is not Pod metric parity. No fake metric period controls should be added.

**Events:** upstream global object-event component subscribes, disposes, sorts descending lastTimestamp and renders message/source/count/sub-object/last seen with warning style (`F/events/kube-event-details.tsx:45-98`; registered globally `F/kube-object-details/kube-object-detail-items/implementations/kube-event-detail-item.injectable.ts:12-21`). Iceon specialized Pod details **does fetch events**: GET core namespaced Events filtered `involvedObject.uid`, limit 100, timeoutSeconds=10 inside a three-second timeout, then verifies UID again while projecting; oversized/continuation→Partial, forbidden→Denied, other failures→Unavailable (`src-tauri/src/connection/pods.rs:197-253,639-665`). UI renders Reason/Type/Count/Last seen, explicitly bounded not live, **no message/source/sub-object** (`PodDetailsView.tsx:108-117`).

**High-risk source discrepancy:** Rust serializes `eventsState` (`pods.rs:34-63,234-247`), but `src/app/cluster/podApi.ts:8,37-44` neither types nor validates it and `PodDetailsView.tsx:108-117` does not render it. Forbidden/unavailable/partial event reads can therefore appear as “No events returned.” This is a real contract/presentation gap, not absence of backend event handling, and not proven by runtime testing. Preserve parent facts while distinguishing these states.

Coordinating follow-up: a temporary mocked-IPC probe confirmed `eventsState: denied` with no events displays “No events returned”; another confirmed patch-only access enables Edit YAML. No mutation was sent. Those are renderer fixture observations, not live server tests; see [15](15-expanded-validation.md).

**Full-log download is not cancellation-equivalent:** upstream dropdown disables while awaiting All logs and restores waiting in finally (`F/dock/logs/download-logs-dropdown.tsx:20-47`), but `download-all-logs.injectable.ts:26-35` calls logs without an AbortSignal, then opens native save dialog or reports no logs. ### RBAC, identity, cancellation and side effects

- Rust requires specific logs/exec/attach authorization at open, uses authorized client, validates target/container/tail/shell, worker/slot bounds; fresh GET verifies UID and container exists across regular/init/ephemeral, non-log requires running process (`src-tauri/src/connection/pod_runtime.rs:402-483,485-584`). UI also checks Pod get. Permission mapping uses `pods/log`, `pods/exec`, `pods/attach`, `pods/portforward`, **GET verb for these stream actions**, matching this client's transport choice (`src-tauri/src/connection/permissions.rs:232-251`). Do not change to create merely because kubectl commonly uses POST; verify actual transport if changing implementation.
- ResourceVersion is **not a stream baseline**; UID/name/ns/session bind target and fresh checks guard replacement. Post-open checks occur after log transport and after exec/attach opens (`pod_runtime.rs:835-842,877-893`), and before each terminal input. **Residual TOCTOU:** name-based Kubernetes subresources have no atomic UID precondition; replacement between GET and open can cause an exec start before later UID mismatch is detected. This is not proof it occurred, nor absolute replacement immunity. Recheck cannot roll back already-started command.
- Specialized open calls are bounded by operation deadline/session cancel (`pod_runtime.rs:33-41`; `src-tauri/src/connection.rs:48` is 15 seconds); ongoing stream reads select cancellation. Exact stream-close checks lease+scope, cancels, clears buffers/input/resize, removes registry (`pod_runtime.rs:595-614`). Runtime drain cancels all and awaits tracked tasks (`:293-317`). Terminal cleanup **aborts and joins kube websocket task**, not detached drop (`:940-950`). UI may ignore cleanup errors; don't call best-effort close acknowledgment a guaranteed remote process kill.
- Logs read can contain secrets emitted by workloads; runtime output is intentional, bounded and transient, not evidence renderer can read kubeconfig/Secret objects. Input can mutate the workload. Stream close/disconnect does not promise remote exec work or an attached process's side effects are undone. No automatic reconnect/replay/input retry is evidenced here.
- Upstream shell/attach are local terminal subprocess workflows; Iceon intentionally uses Rust direct Kubernetes transport and does not execute host kubectl or interpolate resource names. This is an architectural safety difference, not a missing host shell feature to fill with Node/Bun.

## Summary and follow-up boundary

This chapter records **13 proposed checklist items** (8 Pod, 5 runtime).
