### Prioritized findings

1. **P1: preserve data boundaries and accurate permission/uncertainty language.** Do not “fix parity” by fetching Secret/ConfigMap keys/type/data, or treat unknown access as denied/read-only. Review deletion preflight minimization separately. Existing-object YAML edit/finalize requires a new reviewed Rust contract, not reuse of creation input or upstream selfLinks.
2. **P1: restore safe diagnostic completeness:** HPA metric current/target values and described-object links; VPA resource/update policy and recommendation coverage; ResourceQuota resource-key/scope-selector coverage; RuntimeClass scheduling/toleration details. These currently remove operational information, not merely visual polish.
3. **P2: safe scheduling fields:** LimitRange storage/ephemeral/ratio fields and PriorityClass description. Preserve missing/zero/false, invalid data and bounds explicitly. Lease field coverage is already strong; do not interpret renewTime as leadership health.
4. **P2: table usability/action placement:** sorting, configurable columns, reference namespace-filter gesture, richer read-only condition displays, pane action placement/deep linking. Keep the existing shell and stronger identity checks. Common requirements are in chapter 06; each kind-specific acceptance scope follows.
