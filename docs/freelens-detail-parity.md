### Exact relationship semantics worth preserving or deliberately improving

- `events/store.ts:46-74`: events bucket by involved-object UID. Nodes instead match involved UID to node **name**, and require kind Node. Do not accidentally apply that special-case to arbitrary kinds. `events/kube-event-details.tsx:45-99` sorts `lastTimestamp` descending, then renders message/source/count/sub-object/last seen or “No events found”.
- `workloads-replicasets/store.ts:32-34,54-58`: child Pods by owner UID; Deployment revisions by owner UID. `workloads-jobs/store.ts:36-42`: CronJob child Jobs use namespace plus owner **name/kind**, not UID. A Rust implementation should reject replacement/stale UIDs when available rather than silently assume equal names are identical objects.
- `workloads-deployments/store.ts:65-69`: Deployment Pods are template-label matching plus exact namespace, not an owner-UID query. Distinguish selector matches from directly owned children in UI text.
- `packages/kube-object/src/specifics/persistent-volume-claim.ts:40-47` (relative to upstream root): PVC Pods require same namespace and a matching claimName in Pod volumes. StorageClass PV filtering is exact `getStorageClassName()` equality in `storage-volumes/store.ts:12-19`.
- `service-details.tsx:80-84` (under `network-services/`) calls `getByOwnerReference(apiVersion, kind, name, namespace)`. It does not prove UID identity. Namespace details use `getAllByNs(namespace.getName())` for Quotas/LimitRanges.
- `workloads-pods/pod-details-list.tsx:167-229` shares persistent table ID `workloads_pod_details_list`, CPU-descending default sorting, and optional node column. It stops its metric watcher on unmount and restarts when owner changes. `drawer/drawer.tsx:107-138` persists width through drawerStorage and holds scroll positions only in an in-memory history-key map. UID-keyed detail remount resets reveal/expanded local state, not a durable per-object details preference.
- Source quirks are not requirements to copy: Job and CronJob template backoff/TTL use `hidden={value !== undefined}` (so a provided value is hidden), CronJob history fields use falsy checks that also hide zero, and EndpointSlice badges show only truthy readiness booleans. Iceon should distinguish absent/false/zero, not reproduce these display losses.

## Current projection bounds

The inspected current Iceon `detail_facts.rs:1-207` caps sections at 12, facts per section at 32, values at 1,024 UTF-8 bytes, sampled items at 12, and escaped fact output within a conservative 64 KiB budget. It emits a dedicated Coverage section when unsupported values or truncation occur, including outer Endpoints/EndpointSlice/Ingress/RBAC samples. Its RBAC string-array path now preserves `apiGroups: [""]` as `(core)`. These source observations supersede older omission caveats in `resource-inspector-reference.md`; this audit does not change that older document. Whole-response identity/related/node fields have their own contracts.

## Cross-cutting gaps and concrete priorities

1. **Implement shared metadata and conditions sections first.** Preserve Iceon’s bounded closed contract, add explicit `metadata` and `conditions` facts only for reviewed fields. Suggested Rust shapes: metadata name/namespace/creation/UID/resourceVersion, labels/annotations/finalizers as bounded key/value rows only if the product owner approves their sensitivity, and owner references as typed related links. Keep managed fields and condition messages out of the renderer unless separately bounded and reviewed. Sources: upstream `kube-object-meta/kube-object-meta.tsx:99-160`, conditions files above; Iceon `details.rs:36-43`, `detail_facts.rs:925-950`.
2. **Implement related-resource sections for workload and storage chains.** Add bounded lists, not generic arbitrary links: Deployment -> ReplicaSets -> Pods, DaemonSet/StatefulSet/ReplicaSet/Job -> Pods, CronJob -> Jobs, Node -> Pods, PVC -> Pods, StorageClass -> PV, Namespace -> Quotas/LimitRanges, Service -> EndpointSlices. Every relation must carry exact kind, namespace, name and optional UID, have per-section caps and explicit partial state. Upstream selectors/ownership are evidenced at `workloads-*/store.ts`, `persistent-volume-claim.ts`, `storage-volumes/store.ts`, `service-details.tsx:80-84`.
3. **Add event sections as a bounded server-owned read.** Keep exact involved-object identity and UID validation, newest-first ordering, warning semantics, and empty/loading/error/stale states. Do not copy upstream’s broad watch model. Iceon currently has Event facts/relations but not an inspector event list.
4. **Add reviewed metrics cards only where current snapshot data is real.** Start with Pod child tables or Node current capacity if a stable Rust contract exists. Never render upstream-style CPU/memory charts from absent data. Upstream metrics injection is `kube-object-details/kube-object-detail-items/metrics/*`; Iceon’s no-fabrication policy is documented in `DESIGN.md:156-160`.
5. **Create parity tests for each added section.** Use fixture-only Rust/renderer tests for field bounds, condition sorting/false state, related identity/scope/UID, stale refresh, cancellation, narrow layout and omitted sensitive fields. Existing `src-tauri/src/connection/detail_facts/tests.rs` and `details/tests.rs` are the right owners. No real cluster or native smoke claim belongs in this audit.

## Deliberate exceptions, not parity defects

- No raw Secret or ConfigMap bodies, data keys, type, or save editor.
- No raw custom object/spec dump, CRD schema, webhook CA bundle, ingress TLS secret name, PV credentials, container environment, mounts, or arbitrary annotations passed through as raw JSON.
- No generic per-kind edit/delete/scale/remove-subject controls in the inspector; approved mutations remain Rust-owned and confirmation-gated.
- No fabricated metrics, event history, watch semantics, or upstream selfLink/URL compatibility.
- No Freelens extension compatibility claim. Upstream’s Electron/Node/MobX/DI implementation is not being copied.

These exceptions are consistent with the project’s Rust-owned architecture and prior security/read-only decisions. They should remain visible in future parity work so “not implemented” is not incorrectly treated as “forgotten.”
